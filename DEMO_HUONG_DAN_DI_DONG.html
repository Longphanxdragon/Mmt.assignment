🖥️ SCENARIO C: Demo P2P qua Command Line (curl)

✅ Dùng cho: Chứng minh API endpoints, request-response trực tiếp

Bước 13: Lý thuyết cần nhớ

HTTP request/response: Request có method (GET/POST), path (/login), header, body. Response có status (200/401), header, body.
Proxy: Nhận request ở port 8080 rồi chuyển tiếp đến backend (9001) phù hợp dựa trên hostname/routing rule.
Non-blocking I/O: Đang chờ I/O (mạng, file) thì không dừng toàn bộ luồng; event loop có thể xử lý việc khác cùng lúc.
Coroutine (async/await): Hàm async trả về coroutine object; phải await hoặc gọi lại event loop, nếu không sẽ có cảnh báo "never awaited".
Peer-to-Peer (P2P): Mỗi app là peer; kết nối với peer khác qua HTTP POST (không có central server/proxy ở giữa). Dùng async để gửi message không blocking.
Log file: Dùng để chứng minh request đã chạy, debug lỗi runtime, và theo dõi quá trình xử lý.
PID file: Lưu mã tiến trình (process ID) để stop đúng process đã start.

Bước 4: Kiểm tra xác thực bằng POST /login

Viết lệnh gì:
curl -i -X POST http://127.0.0.1:8080/login -H "Host: localhost:8080" -H "Content-Type: application/json" -d '{"text":"abc"}'
Ở đâu: Terminal 2
Giải thích: Dùng để thử cơ chế xác thực. Nếu chưa có quyền hoặc chưa gửi đúng thông tin, server sẽ từ chối.
Cách đọc kết quả: Nếu bị chặn thì phải thấy HTTP/1.1 401 ERROR. Header có thể có WWW-Authenticate. Điều này cho thấy endpoint đang kiểm tra quyền truy cập đúng nghĩa HTTP.
Ý nghĩa để nói với thầy:
"Phần login chứng minh hệ thống không chỉ có route đơn giản mà còn có cơ chế auth. Khi chưa xác thực, server trả 401. Điều đó đúng với phần authentication được mô tả trong báo cáo."

Cách đọc kết quả: Tìm các dòng có GET /get-list, POST /echo, POST /login. Nếu thấy RuntimeWarning hoặc lỗi coroutine thì đó là lỗi async cần nói trong báo cáo, không phải lỗi của terminal.
Ý nghĩa để nói với thầy:
"Log là bằng chứng tầng dưới. Nó cho thấy request đã được xử lý thật trong backend, giúp em đối chiếu giữa lệnh curl, response và luồng xử lý nội bộ."

Bước 7: Non-blocking nằm ở đâu

Giải thích ngắn: Non-blocking không phải là giao diện đẹp, mà là cách server xử lý request bất đồng bộ qua asyncio, coroutine và await.
Trong report: Phần TRIỂN KHAI CƠ CHẾ NON-BLOCKING nói rõ server dùng coroutine và event loop, không chặn toàn bộ hệ thống khi đang chờ I/O.
Trong demo: ./run-dev.sh mở đồng thời proxy 8080 và backend 9001, curl vào 8080 vẫn trả response ngay, logs cho thấy request được đọc và xử lý theo luồng I/O không đồng bộ.
Câu chốt để nói với thầy:
"Non-blocking được thể hiện ở chỗ server vẫn chấp nhận request mới trong khi đang chờ I/O của request trước. Em chứng minh bằng việc mở hệ thống, bắn request qua proxy, rồi xem response và log chạy bình thường."

Khi chạy POST /echo: "Em gửi POST /echo kèm JSON text. Server trả lại chính payload đã gửi, chứng minh route POST và parse JSON hoạt động đúng."
Khi chạy login: "Em gửi POST /login không có auth, server trả 401 Unauthorized, đúng với cơ chế xác thực HTTP."
Khi chốt demo: "Em dùng log và PID file để quản lý tiến trình, sau đó stop-dev.sh để tắt sạch hệ thống."

Bước 9: Lý thuyết cần nhớ

HTTP request/response: Request có method, path, header, body. Response có status, header, body.
Proxy: Nhận request ở 8080 rồi chuyển tiếp đến backend phù hợp.
Non-blocking: Đang chờ I/O thì không dừng toàn bộ luồng; event loop có thể xử lý việc khác.
Coroutine: Hàm async trả về coroutine object; không await thì sẽ có cảnh báo never awaited.
Log: Dùng để chứng minh request đã chạy và để debug lỗi runtime.
PID file: Lưu mã tiến trình để stop đúng process đã start.
